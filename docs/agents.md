# Operating agents

Day-to-day work happens in the panel. This is what is underneath it, for when the
panel is not enough or is not reachable.

## Layout

```
/opt/moni-agents/
├── runtime/              shared Python runtime (a clone of Claude_Agents + venv)
├── shared/
│   ├── claude-auth.env   Claude credential, 0640 root:moniagent
│   ├── models/           the embedding model, downloaded once
│   └── home/             HOME for the moniagent account
├── vault-template/       what a new agent's vault is copied from
├── workspaces/           permitted location for agent project directories
├── agents/<slug>/
│   ├── agent.env         generated config, 0600 — holds the bot token
│   ├── agent.json        metadata, no secrets
│   ├── mcp.json          wires the memory server to this agent's vault
│   ├── data/bot.db       conversation sessions
│   ├── vectors/memory.db the vector index
│   ├── logs/
│   └── vault/            CLAUDE.md · MEMORY.md · WORKLOG.md · memory/
└── archived/<slug>-<ts>/ deleted agents, kept whole
```

Everything under `agents/<slug>/` is generated by the panel through
`moni-helper`. Editing `agent.env` by hand works until the next configuration
change from the panel regenerates it — treat the panel as the source of truth.

## systemd

One template unit, one instance per agent:

```bash
systemctl status  moni-agent@odoo-dev
systemctl restart moni-agent@odoo-dev
journalctl -u     moni-agent@odoo-dev -f
systemctl list-units 'moni-agent@*'
```

The unit runs as `moniagent` under a sandbox: `ProtectSystem=strict` (read-only
filesystem apart from the agent's own directory and `shared/`), `ProtectHome`,
`NoNewPrivileges`, `PrivateTmp`, `RestrictNamespaces`. An attached project
directory is granted by a per-agent drop-in at
`/etc/systemd/system/moni-agent@<slug>.service.d/project.conf`, written by the
helper — not by widening the template.

## The privileged helper

The panel can run exactly one command as root. Every agent operation is a
subcommand of it:

```bash
sudo /usr/local/sbin/moni-helper agent-list
sudo /usr/local/sbin/moni-helper agent-get odoo-dev
sudo /usr/local/sbin/moni-helper agent-action odoo-dev restart
sudo /usr/local/sbin/moni-helper agent-logs odoo-dev 200
sudo /usr/local/sbin/moni-helper agent-memory-index odoo-dev --force
sudo /usr/local/sbin/moni-helper agent-delete odoo-dev
```

`agent-create` and `agent-update` read their configuration as JSON on **stdin**,
because the bot token is in it and command lines are world-readable in `/proc`.

All of them print a single JSON object: `{"ok": true, "data": …}` or
`{"ok": false, "error": …}`.

## Upgrading the runtime

```bash
sudo bash /opt/moni-ai-os/deploy/bootstrap.sh   # pulls Claude_Agents, rebuilds the venv
sudo systemctl restart 'moni-agent@*'
```

Bootstrap is idempotent — re-running it is the upgrade path, not a reinstall. It
does not touch existing agent directories.

## Upgrading the panel

```bash
cd /opt/moni-ai-os && sudo git pull
sudo bash deploy/deploy-dashboard.sh
```

That syntax-checks every file before restarting. A broken `server.js` otherwise
leaves systemd in a restart loop with the panel down and no obvious way back in.

## Adding a project for an agent to work on

The agent may only read and write inside its own vault. To give it a codebase,
put the codebase under one of the permitted roots — `/opt/projects`, `/srv`, or
`/opt/moni-agents/workspaces` — and set it as the agent's project directory in
Settings. It is linked into the vault as `project/`, and the systemd drop-in
grants write access to exactly that path.

The roots are a whitelist in the helper. Widening it is a deliberate decision
about how much of the host a model-authored command may reach, so it lives in
code review, not in a form field.

## Troubleshooting

| Symptom | First thing to check |
|---|---|
| Unit `failed` immediately | `journalctl -u moni-agent@<slug> -n 50`. Bad bot token and missing Claude credential both say so plainly |
| Starts, never answers | The user's Telegram ID is not in `ALLOWED_USERS`. Unlisted users are ignored silently |
| Answers, then goes quiet | Two pollers on one bot token |
| `read-only file system` in the logs | Something is writing outside the sandbox. Do not widen `ReadWritePaths`; attach the path as a project directory instead |
| Search returns nothing | `agent-memory-index <slug> --force`, then check the chunk count |
| Agent forgets across sessions | `MEMORY.md` is empty — the agent is not writing. Tighten the memory rule in its `CLAUDE.md` |

## Backup

Everything that matters for one agent is under `agents/<slug>/`. The vault is
plain Markdown and worth versioning; `vectors/memory.db` is a cache and is not.

```bash
tar czf agent-odoo-dev-$(date +%F).tar.gz \
  --exclude vectors \
  -C /opt/moni-agents/agents odoo-dev
```

Note this includes `agent.env`, which holds the bot token. Treat the archive as a
secret or exclude it and re-enter the token on restore.
